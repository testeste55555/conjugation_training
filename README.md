## 役割

- `vocabulary.json`
  - 単語の正本です。
  - 学習者向けの単語一覧としては表示しません。
  - 今後の単語追加は原則ここだけで行えます。
- `forms.json`
  - グループ名、利用できる活用形、画面上の名称・問題文を管理します。
- `rule-examples.json`
  - 「活用ルール画面で、どの単語を例として見せるか」を管理します。
  - 語彙正本と教材上の例示選択を分離しています。
- `conjugation.js`
  - 活用形を生成します。
- `practice.js`
  - 教室人数分の問題生成、カード送り、ランダム処理を担当します。
- `rules-ui.js`
  - 「みる → かえる → できあがり」のルール画面を担当します。
- `app.js`
  - データ読込、ページ切替、キーボード操作をまとめます。

## 単語を追加するとき

既存の活用規則で処理できる単語なら、`data/vocabulary.json` に1件追加します。

例：

```json
{
  "id": "W0065",
  "lemma": "なおす",
  "pos": "verb",
  "conjugationType": "g1",
  "order": 20,
  "enabled": true,
  "tags": ["work"]
}
```

`id` は重複させないでください。いったん付与したIDは、語の並び替えをしても変更しない想定です。

### 例外活用

規則どおりに生成できない形だけ `overrides` に書けます。

```json
{
  "id": "W0019",
  "lemma": "いく",
  "pos": "verb",
  "conjugationType": "g1",
  "enabled": true,
  "overrides": {
    "te": "いって",
    "ta": "いった"
  }
}
```

原則として、通常の「ます形・て形・ない形」などを全てJSONへ書く必要はありません。

## ルール画面の例に追加するとき

練習用語彙へ単語を追加しただけでは、ルール説明の例は自動では増やしていません。

ルール画面でも例として使いたい場合のみ、`data/rule-examples.json` の `wordIds` に語彙IDを追加します。

これにより、

- 練習に出す語彙
- ルール説明で代表例として見せる語彙

を別々に管理できます。

## リポジトリ運用

このリポジトリは public repository で運用するため、

## GitHub Pages

このフォルダの中身をリポジトリへ配置し、GitHub Pagesの公開元に設定すれば動作します。

JSONを `fetch()` で読み込むため、Windowsで `index.html` を直接ダブルクリックして `file://` で開く方法は推奨しません。

ローカル確認をする場合は、このフォルダで例えば次を実行します。

```bash
python -m http.server 8000
```

その後、ブラウザで `http://localhost:8000/` を開きます。

## 授業画面の操作

「れんしゅうを はじめる」を押すと、カードへフォーカスが移ります。Spaceで解答を表示し、右矢印で次の問題へ進みます。ボタンへTabで移動した場合は、そのボタンの通常のキーボード操作を優先します。

問題を提示する際のアニメーションは、中央の黄色い活用形ハイライトに適用します。右上の小さな活用形バッジは動かしません。OSやブラウザの「動きを減らす」設定ではアニメーションを停止します。

## データ追加時の検査

`data/vocabulary.json` に語彙を追加したら、`npm test` を実行してください。重複ID・原形、分類の不一致、参照IDの欠落などは読込時にも検出します。例外活用は必要な形だけ `overrides` に保持します。練習に出さない語彙をルール例として使う設計は、従来どおり可能です。

## v2.7.2 の追加仕様

動詞1～3グループに「めいれい形」「きんし形」を追加しました。練習画面とルール画面の両方から選べます。初期選択は従来どおり「ます形」だけです。

命令形は、1グループがエ段（おく→おけ）、2グループが「る→ろ」（みる→みろ）、3グループが「する→しろ」「くる→こい」です。禁止形は全グループで辞書形に「な」を付けます（おくな・みるな・するな・くるな）。複合する動詞も同じ規則を使います。これは強い言い方の形を学ぶためのもので、丁寧な依頼表現と同じものとして扱いません。

### 必要なときだけ派生形を表示する

練習の活用形選択では、ません形・ました形・ませんでした形・なかった形を初期状態で折りたたみます。「ほかの かたちを みる」で表示できます。選択した形は、再び折りたたんでも選択状態を保持し、選択済みのボタンは表示したままにします。表示の開閉だけで現在の問題は作り直されません。

ルール画面では、ます系の基本は「ます形」、ない系の基本は「ない形」を表示します。下部の「ほかの かたちを みる」を押すと、それぞれの系列に含まれる残りの完成形を確認できます。もう一度押すと閉じます。別の系列を選ぶと初期状態に戻ります。辞書形・てた系・可能形・命令形・禁止形は従来どおり独立したルールとして扱います。

語彙正本、形容詞の設計保留、個人学習用内部データ、中央ハイライトのアニメーションは維持しています。

## v2.7.3：ルールの起点を選ぶ

動詞のルール画面では「ます形から／じしょ形から」を切り替えられます。初期値は「ます形から」です。グループやルールを切り替えても選択した起点を保持し、形容詞では起点選択を表示しません。起点を切り替えたときは説明を1段階目から表示し、開いていた派生形は閉じます。

例：「かく」のて形は、ます形からなら「かきます→かいて」、辞書形からなら「かく→かいて」。命令形は「かきます→かけ／かく→かけ」。禁止形は、ます形からなら「かきます→かく→かくな」と辞書形を経由し、辞書形からなら「かく→かくな」です。

目標の形と起点が同じ場合は「そのまま」と表示します。ます系・ない系の派生形は従来どおり必要時のみ展開できます。どちらの起点でも同じ活用エンジンを利用し、正答データを二重に保存しません。起点ごとの説明経路は `js/rules-source.js`、起点の表示設定は `data/forms.json` の `ruleSources` で管理します。

練習画面の出題元・問題生成・語彙正本・形容詞の保留状態は変更していません。辞書形の練習問題も従来どおり、ます形から辞書形へ変換します。

## v2.7.4：て形・た形の説明を分ける

ルール画面では「て・た系」を一つの表示項目にせず、「て形」と「た形」を別々に選びます。1回の説明で扱う目標形は一つだけです。1グループでは従来の「う・つ・る」「む・ぶ」「く」「ぐ」「す」「いく」の共通パターンを再利用し、例示語も一つずつ切り替えます。

例えば「う・つ・る」を選ぶと、最初は「つかいます → つかって」だけを3段階で説明します。「まちます」「とります」などは例示語のボタンから切り替えます。た形へ移るときは「た形」を選び直し、同じパターンを別の目標形として学べます。

「ます形から／じしょ形から」の切り替え、派生形の必要時展開、練習画面の選択肢・出題元・問題生成は従来のままです。共通パターンデータにはて形・た形の両方の情報を保持しており、正答を二重に保存しません。

## v2.7.5：まとめてみる

「かつようの ルール」に「一つずつみる／まとめてみる」の切り替えを追加しました。個別ルールは従来の3段階のままです。

一覧では、動詞・形容詞を切り替え、目標活用形を一つ選んでグループごとの代表例を比較します。動詞は「ます形から／じしょ形から」の起点も共通の選択欄で切り替えられます。ます系・ない系の追加形は必要時だけ展開できます。

1グループは最初に代表パターンを一つ表示し、「1グループの へんかを みる」で全パターンを開きます。て形・た形はそれぞれ6パターン、その他の形は8語尾を確認できます。2グループは共通規則、3グループは「する」「くる」を区別します。表示される例はすべて既存の例示語IDと活用エンジンから生成します。

形容詞は既存の設計保留を維持し、い形容詞・な形容詞を明確に分けます。「つなぐかたち」は既存の「くて／で」を対応させる一覧専用の表示分類です。「く」「な」はそれぞれ適用される品詞だけを表示します。既存の「いい」「きれい」の例も保持しています。命令形・禁止形を形容詞へ適用することはありません。

各行の「くわしくみる」から、グループ・活用形・起点・パターン・例示語を引き継いで個別ルールへ移れます。「まとめにもどる」で一覧の選択と展開状態へ戻ります。派生形から移った場合は対応する系列を開き、その形を示します。

一覧の追加により練習画面の問題生成・出題元・語彙・正答は変更していません。比較一覧のデータ生成は `js/rules-overview-data.js`、画面処理は `js/rules-overview.js` に分離しています。正答表を二重に持たず、従来の活用エンジンを共用します。
